# Интерактивная ширма мастера

Настольный рабочий стол ведущего D&D для Windows. Пять панелей по исходному макету: трекер боя, музыка, dnd.su, карта и Long Story Short.

## Скачать

Откройте [последний выпуск](https://github.com/Vilsonchik-Jmixus/interactive-dm-screen/releases/latest), скачайте `DM-Screen-Setup-<версия>.exe` и установите программу. Установщик первой версии не имеет коммерческой цифровой подписи.

## Возможности прототипа

- Бойцы: имя, портрет, ХП, инициатива, дублирование, очередь ходов и раунды.
- Изменение ХП: `-7`, `+5`, `=20` и отмена последнего изменения.
- Кнопка «На карту»: жетон занимает свободную клетку; повторное добавление исключено. Перетаскивание привязывается к сетке; двойное нажатие убирает жетон.
- Карта из файла, перетаскивания или буфера обмена (`Ctrl+V`). Масштаб, размер клетки, цвет, прозрачность и смещение сетки.
- Каждая из пяти панелей выносится в отдельное окно для другого монитора. Закрытие окна возвращает панель. Данные общие для всех окон.
- Изменение раскладки разделителями и уголком панели. Разворачивание с анимацией, кнопка ⛶, Escape. Если дотянуть уголок до нижнего правого края рабочей области, панель развернётся. Отдельные окна изменяют размер обычными границами Windows; F11 включает полный экран.
- dnd.su и Long Story Short работают как изолированные браузерные панели. Вход выполняется на самом сайте; браузерная сессия сохраняется. Провайдер входа может ограничивать авторизацию во встроенных браузерах — предусмотрена кнопка открытия сайта в обычном браузере; его сессия с приложением не общая.
- Музыка: локальные файлы, импорт аудио с YouTube через yt-dlp, папки, перенос треков между папками, громкость и повтор. Импорт зависит от доступности видео, сети и изменений YouTube. Ограниченные видео могут не загружаться. Используйте файлы и материалы, на использование которых у вас есть права.
- Кампания и медиа автоматически сохраняются в `%APPDATA%/interactive-dm-screen`. Они отделены от установки и не удаляются при обновлении.

Это первый прототип: одна локальная кампания, без сетевой игры, тумана войны и автоматического переноса характеристик из Long Story Short в трекер. Расположение отдельных окон сохраняется; после нового запуска панели сначала находятся в ширме.

## Разработка

Нужны Windows x64, Node.js 24 и npm. Встроенные сайты и загрузчик требуют интернет; трекер, карта и импортированные треки работают локально.

```powershell
npm ci --ignore-scripts
node node_modules/electron/install.js
npm run tools
npm start
```

Проверка логики и сборка:

```powershell
npm test
node tests/desktop-smoke.cjs
npm run build
```

Архитектура: Electron, WebContentsView для удалённых сайтов, обычные HTML/CSS/JS для интерфейса, единый reducer в главном процессе и атомарное сохранение JSON. Удалённые сайты не имеют доступа к Node.js или API приложения. Локальные медиа копируются в управляемую папку assets. Загрузчик yt-dlp поставляется отдельно от asar, его SHA256 проверяется при подготовке сборки.

## Выпуск обновлений

В установленной NSIS-версии electron-updater проверяет GitHub Releases при старте и каждые четыре часа. Новая версия предлагается пользователю: скачать → перезапустить и установить. Автоматического закрытия игры нет. Кнопка «Обновления» запускает ручную проверку. В режиме разработки обновления отключены.

```powershell
npm version patch
git push origin main --follow-tags
```

Workflow `.github/workflows/release.yml` запускается на тег `v*`, проверяет совпадение версии, выполняет тесты и публикует установщик, `.blockmap` и `latest.yml`. Не удаляйте эти файлы из выпуска: они нужны механизму обновлений. Репозиторий и выпуски должны оставаться публичными для обновления без пользовательского токена. `GH_TOKEN` используется только сборкой в GitHub Actions; в приложение секреты не включаются.

Первый переход между двумя опубликованными версиями требует отдельной проверки на установленной программе. Наличие механизма обновлений само по себе не означает, что такой переход уже был протестирован.
